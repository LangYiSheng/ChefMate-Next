# 账号、管理员和 Docker 改造计划

本轮从 2026-10-27 的 `d1ae4fa` 开始，目标是把单用户本地工作台变成可登录、可管理额度的自托管应用。此次不修改版本号或发布日志。

执行中用户追加：Docker 默认使用独立 PostgreSQL 保存账号和全部个人业务数据；厨房档案在用户明确授权后进入长期记忆与配置的模型；用户额度只按金额计算，Token 仅统计；持续工作截止延长至当日 21:30。随后追加宽长屏欢迎区域居中、旧日常个人 SQLite 实际迁移，以及 358 道基础菜谱随 GitHub、Docker 空库首次自动导入。以下早期草案涉及 SQLite 运行数据、可选基础库和 Token 额度的部分由上述追加要求取代，当前合同见[账号设计](../../design/accounts-admin.md)。

## 产品流程

1. 访问应用先登录，账号和密码注册后进入欢迎引导。
2. 欢迎流程介绍对话、厨房任务、个人菜谱和食光手记，保存称呼、烹饪经验与家庭人数。完成后进入原有工作台；中途刷新仍需完成引导。
3. 用户可调整个人外观与交互偏好，查看自己的用量和额度。模型连接、系统运行参数与计价归管理员。
4. 管理员在独立管理页查看用户、停用账号、调整额度与开发者权限、重置密码，维护模型、价格和数据。
5. 以后通过 Docker Compose 构建和启动；身份库、个人数据、图片和设置写入持久卷。

## 身份与权限

密码采用带随机盐的 scrypt 哈希。Cookie 仅保存高熵随机会话，服务端保存其哈希；会话设置 HttpOnly、SameSite、有效期，并可撤销。密码和权限变化使旧会话失效。登录、注册限流，校验失败不回显密码。

管理员仅通过显式环境变量引导创建；第一个注册者不会成为管理员。数据库事务保护最后一个可用管理员。任何管理员和开发者权限都以服务端当前账号记录为准，浏览器的开发者开关与请求头仅表示用户意图。

同源校验和 Host 白名单覆盖全部写请求；HTTPS 部署使用 Secure Cookie。开发者调试接口、工具直调与原始上下文需要服务器授权。普通用户不能修改全局模型、端点、密钥、运行参数或系统组件。

## 数据隔离与旧数据

身份和内容无关的用量保存在 `accounts.db`，每个随机用户 ID 有独立的 `users/<id>/sessions.db`、图片与偏好。对话、工作流、收藏、个人菜谱、记忆与手记使用该用户对应的仓储和 Agent 工具绑定。公共 PostgreSQL 菜谱目录可共享。

旧 `sessions.db` 原样保留，不因注册、引导或部署自动认领。部署前备份整个运行目录。新用户不会看到旧库或其他用户的内容，管理员的数据重置先归档后重建，不删除身份与用量账本。

## 用量和成本

每轮以唯一 turn ID 建立额度预留，事务中检查该用户已使用量和并发预留。进入模型调用前按请求大小与输出限制扩大预留，额度不足时停止调用；取消、失败和重试也有独立且幂等的结算。

Token 和费用保留模型真实报告以及缺失标记。没有 usage 的调用使用单列保守预留估算参与额度控制，不能伪装成实测零用量。价格以每百万输入、缓存输入和输出 Token 设置，按轮保存价格快照，后续调价不追改历史。成本为站内按配置计价的估算，不能声称与供应商发票完全一致。

## 界面约定

复用现有字体、主题 Token、图标、按钮与设置分组，欢迎页采用厨房伙伴图形和轻量分步入场。窄屏不产生横向溢出，支持键盘、焦点提示、字段错误和减少动态效果偏好。登录过期与账号切换清空浏览器私有缓存，防止前一账号短暂残留。

## 分层验收

- 身份：注册、重复账号、错误密码、退出、过期会话、重置密码与停用。
- 权限：伪造开发者头、非管理员模型修改、直接 URL、跨源写请求和 Host 校验。
- 隔离：两账号分别创建内容，相同路径与已知 ID 仍不能跨用户访问；偏好、图片和工具绑定同样隔离。
- 额度：零额度、并发请求、重复请求、价格调整、缺失 usage、失败与取消后的账本。
- 界面：完整注册到欢迎再到工作台，管理员操作，桌面与手机宽度，减少动态效果。
- 部署：实际构建镜像、健康检查、容器运行与重启持久性，缺模型与缺公共菜谱时显示真实限制。

完成情况、具体命令和外部限制写入同日工程验收记录，不使用计划中的勾选替代实测。
