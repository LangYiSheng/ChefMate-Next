# 营养手记、系统组件与可观测性

用户已授权实现、真实模型与浏览器验证，并要求每次更新都提交。按可独立验证的大块提交，保留原有 `.gitignore` 与 `test/`，不提交运行数据和凭据。

## 边界

1. 系统组件注册表统一指南、提示词、工具归属、UI种类/页面、依赖与工厂；应用设置/API统一 components。底层通用指南加载器仍是技术实现，不再以Skills代表整套能力。关闭组件同时撤去模型可见工具与执行权限。
2. food-journal作为首个新增组件：图片或文字生成个人餐盘草稿，用户核对后保存；记录食物、日期、实际吃的份量与营养来源/假设。视觉估算始终标估算，未知不填零。与烹饪制作量分开聚合。
3. 手记默认突出今日个人营养和所选期间趋势；明确资料完整度和已知小计，未完成/缺资料不能显示成完整摄入。
4. Token用量来自供应商报告，独立账本按会话/轮次幂等记录，失败和取消已观测用量也保留；未知字段保持未知，历史身份缺失不推断。设置提供汇总与模型分布。
5. 开发者侧栏展示实际模型请求的上下文分类字符数与明确标注的粗略token估算，含系统、指南、对话、工具、UI与记忆；图片和供应商封装不伪造精确计量，不臆测窗口容量。
6. 整理设置分类与说明，增加关于页，统一控件和只读统计页，保留独立草稿、版本校验与忙时退出保护。

## 验收

- 注册表闭合、重复/无主工具拒绝、关闭新组件拒绝工具，原厨房能力回归。
- 食记来源/取消/幂等/CAS、视觉估算约束、个人与多人制作量隔离、未知/完整度/日期聚合。
- 用量重复事件不重计、缺失不补零、删除会话后账本保留；上下文分类与实际请求匹配且无凭据。
- 真模型图片记餐生成草稿并保存；用户修改后真实读取。UI桌面/手机，未保存保护与数值可读性。
