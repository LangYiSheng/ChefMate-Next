# React 迁移后的功能与视觉一致性复核

记录日期：2026-10-23。版本保持 0.2.0。本轮针对首次 React 迁移后的排版、字体、主题与交互差异进行复核和修复；对照基线为 `6606b7a`，现行实现仍为单一 React 应用，比较基线不作为运行依赖。

本记录区分实现、自动回归与真实浏览器验证。前一次[迁移验收](2026-10-23-react-migration.md)保留当时结果，不能代替本轮修复后的重新验收；以下矩阵也不表示所有环境和交互组合均已覆盖。

## 复核边界与环境

- `127.0.0.1:18766`：本轮 React 验收服务，使用隔离的会话数据库与设置目录；真实模型操作、主题保存和个人数据测试均在这里进行。
- `127.0.0.1:18767`：历史界面只读对照，用于确认行为和视觉差异。
- `127.0.0.1:18765`：常用服务仅进行只读健康检查，状态为 `ready`；没有把隔离测试配置写入常用服务。
- 截图、运行数据库、个人配置、依赖安装目录和构建输出不入提交。基础菜谱库继续只读，测试记录与常用个人数据分开。

## 实际修复与确定性回归矩阵

### 会话运行与草稿

| 复核项 | 修复后行为与回归边界 |
| --- | --- |
| 状态快照与生命周期 | React 已读取的快照保持稳定；卸载仅分离监听，迟到事件不能污染重建后的状态。显式停止才请求取消，切页或切会话不取消任务。 |
| 断流与待定 POST | 断流后读取所属会话恢复；收到响应头前已被服务端接受的 POST 使用稳定请求标识对账，刷新不盲目重发。明确未接受的请求保留原标识重试。 |
| 会话选择与迟到读取 | 选择尚未读取完成时阻止发送；旧读取不能覆盖后来选择，重新进入同一会话也核对读取代次。 |
| 首次发送与浏览器草稿 | 首次准备失败保留文字与本地图片；离开尚未接受首条消息的空会话后，仍可恢复草稿。已提交附件与用户后来输入的文字分别处理。 |
| 附件归属与删除 | 处理中图片继续属于原会话；远程附件删除与发送互斥，删除会话后的迟到响应不能把会话或附件恢复。 |
| 确认后的自动续轮 | 动作保存后只续轮一次，不带走原输入草稿；失败保留可重试状态。等待中的会话刷新、卸载重建与旧续轮完成各自核对生命周期和请求标识。 |
| 会话名称与置顶 | 名称或置顶保存成功后，先前发起的 GET 不能覆写新值；随后侧栏刷新失败也保留已接受的保存结果。 |
| 会话列表失败与分页 | 初次读取和追加失败分别暴露重试入口；保留已有条目与服务端游标，不用空列表伪装成功，不因重试跳页。 |

### 设置、厨房与个人中心

| 区域 | 实际修复与回归 |
| --- | --- |
| 设置修订与部分保存 | 分类草稿分别保留，只推进服务端实际接受的修订基线；本地显示偏好保存不把其他服务端草稿推进到新版本。HTTP 409 后保留用户草稿；服务端已接受而浏览器写入失败时，保留已接受结果并报告部分失败。 |
| 设置读取与导航 | StrictMode 首次中止读取不覆盖后续结果；内外部导航共用一次确认。记忆保存和清空使用自身 revision，冲突可复核，初始读取失败可重试；迟到用量或洞察响应不覆盖新分类。 |
| 备料 | 恢复完整可滚动清单，待备置顶，已备齐或明确跳过的项目划线沉底；按真实食材 ID 操作，同名食材不互相确认。移除备料逐项大字和分页模式。 |
| 回复内组件 | `inline_limit` 实际控制默认展开一项或两项，当前可编辑内容优先，其余保留摘要、展开和全屏入口；相同 view ID 只由最新消息提供当前任务操作，历史保留原快照。 |
| 步骤与阅读分页 | 逐步阅读与完整列表分开，浏览不完成步骤，明确确认后跟随下一步；全屏长说明按空间分页，保留全部字符与滚动兜底。主要执行动作保持可达，横屏压缩辅助建议和留白，为阅读腾出空间。 |
| 厨房快照与冲突 | 模型轮次完成前不展示新表单；最终刷新遇到旧 GET 时补读最终状态。冲突保草稿，网络结果不确定时复用原 action ID；数量留空保留空草稿，错误就地展示，改回基线可放弃无效修改。 |
| 计时浮层 | 共用一个 tick 与服务端校准时钟；新计时和到期可自动展开，保留当前草稿和焦点。焦点仍在交流区时，Escape 也先关计时浮层，不退出专注模式。每步优先显示一个适用计时器，策略与容量读取服务端。 |
| 提醒与声音 | 后台会话可提醒，查看提醒才切换会话；声音需要浏览器交互解锁并遵守静音设置，同次多个到期只播放一次提示声。删除会话及迟到读取不复活旧任务，响铃不完成步骤。 |
| 完成与登记 | 区分制作完成、已登记、待补本人份额与同步失败。完成动作已落库但随后记录同步返回 503 时，不仅凭 recent actions 清除失败状态；重试相同完成请求补齐后续登记，再续聊。 |
| 菜谱与饮食编辑 | 食材身份变化才清除其克重或 USDA 关联；未知营养保留 null。保存后发布失败保留已接受 revision，重试发布不重复 PUT；个人编辑器保护脏草稿，基础菜谱不露删除入口，迟到详情不覆盖新选择，标题随已接受编辑更新。 |
| 中心入口 | 开始做菜回到聊天工作流并带入明确意图；收藏、草稿、回收站、饮食草稿与已保存记录继续使用对应领域接口和 revision。 |

## 视觉与资源归属

删除迁入 `public/` 的 22 个旧 CSS、旧 `favicon.svg`、未使用的四个品牌候选 SVG，以及 `src/react.css`；入口不再逐个加载旧样式。保留实际使用的品牌、字体和 Lucide sprite 及来源许可证。

全局样式由 [styles/index.css](../../../apps/chefmate-playground/frontend/src/styles/index.css) 统一引入，按 `foundation/controls/shell/chat/details.css` 分别管理语义颜色与字体、公共控件、框架、聊天和详情。设置、个人中心和厨房使用各自作用域 CSS，公共主题来自 `--color-*` 与 `--font-*`，不靠跨页面同名选择器叠加修补。

标题、阅读正文、控件和数值使用各自字体角色；主按钮使用强调色及对应前景色，估算标记服从全局显示开关。手机输入保持 16px 和完整可用宽度，横屏保留阅读、确认与滚动空间。布局和行为的现行要求同步到[交互与视觉规范](../../design/ui.md)，本记录只保存本轮验证证据。

构建将 React 与 Markdown 解析依赖拆成独立 vendor 组，设置和个人中心按需加载；独立生产构建已通过，未出现构建警告。构建输出继续位于被忽略的 `web/`，不提交生成文件。
