# 72 个隔离账号持续运行检查

日期：2026-10-27。全部时间使用 UTC，换算为北京时间需加 8 小时。

## 检查范围

使用 [verify_multi_user.py](../../../scripts/verify_multi_user.py) 建立 72 个合成普通账号，最多 4 个客户端同时执行一组操作，每组约间隔 4 秒。每个账号保存自己的厨房档案、会话标题、记忆、主题和测试图片。循环检查自己的数据、另一个账号的会话及图片 404、普通账号访问管理接口 403，以及偏好过期版本修改 409；轮换执行持久化写入。

持续写入具体为记忆和主题的 CAS 修改；会话标题与图片反复读取核对，厨房档案由准备夹具写入，持续循环未逐字段复核；重新登录核对账号身份。阶段 1 每 8 组执行一次写入，阶段 2 改为每 7 组，避免与 18 组账号轮换产生固定重复，保证全部账号都轮到修改。写入比例略有不同，两个阶段的耗时不能当作严格 A/B 性能比较。

初始账号和 Cookie 通过只面向隔离数据库的可信夹具建立，没有关闭产品注册或登录限流，也没有增加测试专用 HTTP 后门。私人状态文件仅保存在被 Git 忽略的运行目录，指标不记录密码、Cookie、请求正文或模型密钥。

## 复现与证据

先按部署指南启动一个名称、端口、数据库及卷都独立的测试项目。脚本的 `seed` 需要显式 `--confirm-disposable` 和指向该专用数据库的 `CHEFMATE_TEST_APP_DSN`；它会拒绝包含无关账号的数据库。使用 `prepare` 建立初始数据，`run` 按指定截止时间循环，`verify` 在重启后核对私人状态文件中保存的数据。通过 `--help` 查看具体参数；不要把私人状态文件放入仓库。

本次原始证据位于本地忽略目录：阶段汇总 `apps/chefmate-playground/.runtime/soak/*-summary.json`、阶段循环 `*-metrics.jsonl`、资源采样 `.runtime/soak-resources.jsonl`、内存分类 `.runtime/soak-memory-breakdown.jsonl` 与 60 秒 CPU 区间 `.runtime/soak-cpu-interval-115101.json`。这些运行目录不纳入提交。

当前实现仍是单进程，Agent 运行与工作区缓存位于内存。本次检查验证指定请求组合的隔离、缓存换出后重新读取及持续资源表现，不证明多进程协调、外部模型并发或大规模生产容量。
