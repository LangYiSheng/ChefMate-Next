## 第三轮：定向修改保留与请求投影去重

真实模型的“只改总耗时”暴露契约冲突：严格工具参数会补齐未修改的 nullable 字段，原 metadata_patch 把这些 null 当作清空。基线中份数和难度一度被清空，之后模型又触发两次拒绝并整份重抄恢复；最终结果正确不代表中间操作正确。

现在仅 Agent 元数据 patch 中，省略或 null 表示保留；用户明确要求清空时使用 clear_fields 列出字段。同一字段不能既清空又提交非空值，来源仍须对应本次修改。HTTP 完整菜谱编辑器不使用该 patch，原有显式 null 清空行为保留，并有回归用例。

使用相同历史、同一 revision2 草稿和同一句原话真实复测：仅 get_recipe_draft→revise_recipe_draft 两次成功调用，revision2→3；只有总耗时 15→20 及其对应来源更新，2 人份、normal 难度、备菜 5 分钟、蒸制 10 分钟、食材、步骤和原文均保留。另以自然语言要求清空总耗时，模型只列 clear_fields=[total_time_min]，只移除该值与对应来源，仍为未发布草稿。

模型请求去重仅作用于临时消息投影：组件内容不变而版本变化时，发送 component_versions 小补丁；真实业务内容变化仍完整发送，字段删除或顺序变化回退到完整快照。原始工具回执、持久历史和工作区不改写。重建等价性、原消息不变、旧格式与孤立 delta 等 15 项新回归纳入完整 Agent 258 项验证，全部通过。相关菜谱/审核/来源/库 58 项通过。
