## 实现范围

- 默认要求注册和登录，显式配置初始化管理员，首个注册用户保持普通身份。密码、会话、限流和权限均由服务端处理。
- 欢迎引导设置厨房档案和主题，账号页可以修改。厨房档案仅在明确开启 AI 个性化后写入独立的长期记忆投影，随请求发给所配置模型；关闭授权、关闭记忆或清空投影后遵守新状态。
- 管理平台管理用户、角色、开发者权限、金额额度、注册政策、价格、模型配置、审计和个人数据归档重置。Token 仅统计，不作为用户额度。
- Docker 默认使用独立应用 PostgreSQL；账号、用量和各用户个人业务记录分 schema 保存。另一项默认公共菜谱 PostgreSQL 在空库首次启动时导入仓库自带的 358 道基础菜谱，图片和设置使用持久文件卷。
- 提供旧 SQLite 显式迁移、备份校验和 Docker 启停工具。不会自动认领旧单用户内容，也不会删除已有卷来处理升级。

## 内置基础菜谱与旧个人记录

用户追加要求把之前 300 多道基础菜谱随 GitHub 提供，Docker 首次启动即可使用。最终打包 358 道 HowToCook 来源菜谱，数据版本 `chefmate-bundled-20261005`。从原 204,920,387 字节导出剔除在线导入从不读取的原文、候选食物快照和上下文冗余，得到 4,300,185 字节的 schema-2 JSON；全部 11 张关系表投影逐项一致，原始哈希与新文件 SHA256 保留在[种子目录](../../../data/seed/catalog/README.md)。固定 LF 属性防止 Windows Git 换行转换破坏校验。

只读核查发现，日常测试菜谱库 `2026.10.05-test` 曾把全部 358 行设为 `ready_for_recommendation=true`；原始导出实际为 2 条 approved、356 条 pending_review，且没有达到完整事实营养的可推荐行。内置数据保留原始真实状态。一般检索工具默认查看全部真实候选并附核对说明，显式要求严格可推荐时仍过滤；底层 Storage/CLI 的严格默认与逐项营养约束保持不变。真实 PostgreSQL 回归验证默认、菜名和食材查询有命中，严格可推荐为 0，缺失营养不能因条件为 0 就自动满足。

另已将旧日常 SQLite 的 47 个会话、329 条消息、私人菜谱、记忆、手记、用量及图片实际迁入全新 PostgreSQL 与文件卷，归属新部署明确初始化的管理员，原数据未改动。旧用量没有当时的中央金额价格快照，保留个人历史统计，不编造历史费用。过程与最终 HTTP 核对见[实际迁移记录](2026-10-27-daily-postgresql-migration.md)。

## 金额和数据正确性

金额以微元整数保存，初始新用户默认 ¥5。有限额度必须先有管理员明确确认的 CNY 计价，免费模型可明确确认全零。每次模型请求先预留，再按当轮价格快照结算；并发请求共享事务边界，重放轮次不会重复记账。

模型未返回完整用量时，已知部分仍保留，未知部分单列暂估占用。SDK 有可信重试次数时据此收窄占用；没有次数时保留配置上界，不把未知用量写成实测零。价格和金额账本是站内计价依据，不替代供应商发票。

管理员根据外部记录核对最终总金额时，追加带原因和版本的核对记录，原始用量、原单价和原金额保留。运行中请求禁止核对，并发修改返回冲突；核对后的金额替代该轮原金额与暂估金额计算余额，不修改 Token 统计。核对历史和审计供后续追溯。

跨用户检查覆盖对话、菜谱、图片、记忆、手记、偏好、用量与开发者接口。客户端不能传目标用户选择工作区。身份切换清理内存状态，图片草稿按账号分区；额外身份绑定头阻止多标签页 Cookie 切换后旧界面写入另一个账号。此请求头仅检查一致性，不能授予权限。

## 已知边界

- 当前是一个 App 进程，Agent 运行、取消与工作区缓存仍在进程内。PostgreSQL 持久化不代表多实例任务调度已经完成。
- 金额额度和管理员核查不包含支付、自动充值、汇率转换或供应商账单自动抓取。
- 早期合成小型公共菜谱库用于运行链路验证；内置 358 道菜谱另有投影相同和导入检查，均不能替代完整召回质量评测。
- 持续运行测试使用固定隔离镜像与合成账号；其混合请求耗时不能冒充生产环境性能基准或外部模型吞吐。
- 文件卷与 PostgreSQL 的迁移切换不能组成跨系统原子事务，极端失败仍需结合备份与迁移报告核查。
