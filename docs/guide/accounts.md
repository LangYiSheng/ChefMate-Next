# 账号与管理员操作

本文描述当前界面的操作。首次启动、管理员初始化与备份方式见 [Docker 部署](deployment.md)；权限和数据边界见 [账号设计](../design/accounts-admin.md)。

## 普通用户

1. 打开 ChefMate，选择“注册一个账号”。账号为 3–32 位英文字母、数字、点号、下划线或短横线；密码为 10–128 位。管理员暂停注册时，已有账号仍能登录。
2. 欢迎引导介绍厨房功能，并可设置称呼、用餐人数、下厨经验、偏好和明暗。之后可在“设置 → 个人资料 / 个人偏好”修改。
3. 登录后使用自己的对话、厨房进度、个人菜谱、手记和记忆。退出会清除当前浏览器的未发送草稿，服务中已保存的资料会保留。

### 厨房档案与 AI 授权

称呼始终随对话发送给当前配置的模型服务商，用于 ChefMate 对你的称呼。烹饪经验、用餐人数、口味偏好、手写偏好与助手长期记忆共同受“在对话中使用个人偏好与长期记忆”开关控制，欢迎引导与个人偏好页使用同一个授权。

“设置 → 个人偏好”集中编辑厨房档案和手写偏好；其中“长期记忆”显示助手的总结。清空长期记忆只清除助手总结，保留手写偏好与厨房档案。关闭开关后，后续请求不附加这些偏好和记忆；称呼仍然生效。

关闭授权后，携带记忆的当前对话会在下一次模型调用前停止。已经发出的调用及其 SDK 重试仍属于此前准入的请求，不能撤回已经发送的资料。

点击侧栏左下角的用户名可打开账号卡片，查看用量概览，进入个人偏好、个人资料、设置或管理平台，并退出登录。设置最上方集中显示“个人资料”“我的额度”“账号安全”。

### 查看金额额度

“设置 → 我的额度”显示当前可用金额、累计计入金额、请求预留，以及每份会员和永久额度的明细。额度单位为人民币，支持小数点后 6 位；内部 `1 元 = 1,000,000 微元`。Token 仅作模型用量统计，不作为用户额度上限。

剩余额度已扣除正在执行请求的预留金额。请求结束后，预留会按结果结算或释放；模型未完整报告的部分会保守预估，不能当作免费。管理员核对后，金额与余额会更新，原始用量记录保留。

新环境普通账号默认有 **¥5 永久基础额度**。管理员可另行发放永久充值额度或限时会员；这里的发放由管理员操作，不包含支付渠道。

会员优先扣减，同时受周额度和 5 小时额度约束；不足的部分依次使用基础额度、永久充值额度。多份会员优先使用较早到期的一份。会员有效期从开通时计算，周与 5 小时窗口从首次实际使用该会员时分别开始；5 小时窗口不越过当前周窗口或会员到期时间。窗口耗尽时使用永久额度，到期后下一次使用开启新窗口。

例如基础 ¥5、30 天会员（周 ¥10 / 5 小时 ¥2）、充值 ¥10：开始时当前可用 ¥17，其中会员当前可用 ¥2，永久额度 ¥15。该 5 小时会员金额用完后继续使用永久额度；新窗口恢复会员可用金额时，后续请求再次优先使用会员。周额度耗尽后，需要等待周窗口重置。

旧单用户数据迁入后，原模型用量保留在个人历史统计中。旧系统没有当轮中央金额单价快照，不为这些历史调用编造费用或补扣额度；新的金额账本从迁入后的调用开始记录。

## 管理员

使用部署时设置的管理员账号登录，侧栏选择“管理平台”。

| 页面 | 操作 |
| --- | --- |
| 用户与额度 | 设置注册政策；“管理”调整角色、状态、开发者权限和密码；“额度”查看各来源明细、发放永久额度或会员、撤销会员。 |
| 模型连接与计价 | 保存多个模型连接，分别设置提供商、协议、Base URL、模型名称、专用密钥、图片能力和价格；测试各连接，启用其中一个。 |
| 运行参数 / 上下文 / 工具与组件 | 在各自的一级页面维护服务运行策略。个人烹饪与交互偏好仍在个人设置页。 |
| 用量与成本 | 查看模型报告的 Token、当前计入金额、未知用量预估与人工核对情况。 |
| 数据与状态 | 查看服务、应用 PostgreSQL、公共菜谱库和按用户隔离的数据量；备份并重置指定工作区。 |
| 操作记录 | 分页查看审计记录，按关键词、操作、操作者、对象和北京时间日期范围筛选。 |

### 先确认价格

每个模型连接分别确认计价。初始零单价尚未确认，有金额上限的用户需要管理员确认当前启用模型的计价后才能发起请求。

单价以“元 / 百万 Token”填写，并用于后续请求。确认全部为零表示后续请求按零金额计算，不扣减用户金额额度；请根据供应商规则填写。单价是站点管理配置，不代表系统自动验证过供应商账单。已有请求保留发生时的计价快照。

### 核对未知或有误金额

1. 在“用户与额度”找到目标用户，选择“用量明细”。表中显示最近 100 条请求的原始金额、未知用量预估和当前计入金额。
2. 等请求结束后选择“核对金额”，填写这一轮的**最终总金额**和必填的核对原因，再保存。执行中或仍有预留的请求不能核对。
3. 系统另存核对记录，用最终金额替代这一轮的原金额与未知金额占用，重新计算余额；原 Token、原单价、原金额和历史核对记录不会被覆盖。后续再次核对不会重复叠加扣费。

其他管理员先保存时，当前草稿会保留。选择“读取最新明细”，确认放弃草稿后重新核对；模型连接与价格、注册设置也有并发保护。金额核对按这轮最初使用的来源与窗口调整，退款不会把已到期窗口的额度转入新窗口。

### 权限与数据操作

开发者权限控制脱敏调试轨迹和工具调试入口，普通用户不能通过打开地址绕过服务端校验。停用账号会撤销其登录；密码重置后该用户需要重新登录。

数据重置会先备份，再清空对话、厨房进度、个人菜谱、手记、图片、自定义记忆和助手总结。账号厨房档案、账号本身、累计用量账本和金额上限保留；目标用户需要重新登录。共享基础菜谱不受影响。全量备份和恢复请按部署文档执行。
