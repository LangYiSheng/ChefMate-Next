# 关键设计决策与取舍

这里记录项目已经采用的选择。收益指机制所提供的能力，效果是否提升仍需在具体场景中验证。

## App 装配能力，独立包持有领域规则

**问题：** HTTP、数据库、模型和厨房规则放在一起，改一个入口就容易牵动所有测试。

**选择：** App 持有配置、会话与个人数据，注入检索、工作流和智能体。底层包不反向导入应用或清洗端。HTTP 路由按资源划分，前端入口组合控制器。

**收益与代价：** 可以独立测试和复用核心能力；装配代码需要明确传递依赖，不能靠全局变量省略边界。[模块地图](../guide/development.md)、[包职责](../../packages/README.md)

## 标准 Agent 加业务 middleware

**问题：** 自己维护模型与工具循环，需要同时处理框架消息、并行、流式、取消和业务约束。

**选择：** 使用 LangChain 标准执行器，项目保留预算、权限、证据、历史与事件适配，厨房门槛留在领域服务。

**收益与代价：** 通用执行可跟随框架维护，业务规则仍可检查；供应商协议和框架升级需要回归。[智能体技术](../guide/agent.md)、[官方 middleware](https://docs.langchain.com/oss/python/langchain/middleware/custom)

## 自然概念由候选连接到确定性查询

**问题：** “想吃虾”既不是单个固定 ID，也不能无差别匹配所有复合虾制品。

**选择：** 先查真实候选，模型解释概念与形态，工具按组内 OR、组间 AND 执行条件。营养共用引用不当作身份等价。

**收益与代价：** 条件可解释、结果可追溯；类别推断依赖证据和模型判断，尚未采用向量索引或经过实验验证的学习排序。[检索参考](../reference/retrieval.md)

## 源快照与任务冻结各解决一种变化

**问题：** 查询引用跨版本会失效，正在做的配方又不能被后台更新悄悄改掉。

**选择：** 查询使用 `data_version + imported_at`，选入任务后冻结配方与来源。

**收益与代价：** 查询能发现更新，当前做饭能持续执行；任务需要保存独立资料，更换餐单也要明确重置执行状态。[工作流参考](../reference/workflow.md)

## revision 防覆盖，action_id 防重复

**问题：** 模型刚读完状态，用户已经勾选；网络重试又把同一操作提交两遍。

**选择：** 命令带预期业务版本，实际修改在原子 mutation 中核对；动作标识登记幂等结果。展示版本另行管理，纯浏览不伪造进度。

**收益与代价：** 新操作不会被旧结果覆盖，重复提交有明确语义；冲突需要读取最新状态复核，不能自动换个版本盲目重放。[界面协议](agent-ui.md#修改表单后模型如何知道)

## 浏览器连接与执行轮次分开

**问题：** 切会话不应取消一轮真实模型请求，用户点击停止又必须生效。

**选择：** 服务端管理轮次，SSE 订阅可分离；恢复读取已保存状态，停止显式取消，重启将未完成轮次标为中断。

**收益与代价：** 界面生命周期不会意外控制业务任务；当前方案没有外部队列与跨进程分布式调度，多 worker 部署需要重新设计协调。[runtime](../../apps/chefmate-playground/src/chefmate_playground/runtime.py)

## 基础库与个人数据分开

**问题：** 发布菜谱快照不应清除收藏，删除对话也不应删掉摄入与用量。

**选择：** PostgreSQL 保存当前基础菜谱，应用 SQLite 保存会话、厨房任务与独立个人记录；不把个人数据级联到可替换菜谱表。

**收益与代价：** 维护和删除语义清楚；扩展多用户服务需要身份、权限、迁移与事务边界的新方案。[存储参考](../reference/storage.md)

## 制作量、配方份量与摄入分别计算

**问题：** 五人四菜不等于每道五份，做完一锅也不等于一个人吃完一锅。

**选择：** 分离整餐人数、单菜目标份数与本人食用比例；单人完成餐按明确产品规则登记，多人等待逐菜份额，计算使用冻结来源。

**收益与代价：** 可以解释一餐与一人的营养差别；共享份量是可调整估计，单人自动登记也不代表称量。[真实案例](../engineering/records/2026-10-22-automatic-intake-and-typography.md)

## 渐进指南与闭合组件权限

**问题：** 全部指导放进提示词会重复，关闭功能若只隐藏指南又不是真正停用。

**选择：** 系统组件统一声明指南、工具、界面与工厂，指南正文按需加载；模型绑定与执行都检查组件状态。

**收益与代价：** 能力可独立测试与关闭；新增工具必须登记归属，同时维护合同和组件清单。[组件实现](../../apps/chefmate-playground/src/chefmate_playground/components.py)

## 原生前端与受控渲染

**问题：** 工作台需要可交互组件，也需要容易运行、查看和调试。

**选择：** 浏览器 ES modules、原生控件与本地资源，模型只提交闭合展示动作，控制器与渲染器分工。

**收益与代价：** 无前端构建步骤，浏览器直接访问源码；状态与生命周期仍需显式设计，规模继续扩大时再评估完整框架。[视觉规范](ui.md)、[开发指南](../guide/development.md)
