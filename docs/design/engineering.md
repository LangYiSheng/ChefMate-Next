# 工程约定

这些约定服务于一个目标：新开发者能顺着请求找到规则，修改时知道影响范围。

## 模块与依赖

- 入口负责装配。HTTP 路由做请求校验、调用与响应转换，不承载完整业务流程。
- 包按领域复用：契约、食物数据、处理、存储、检索、工作流、智能体。底层包不导入 App、清洗页面或读取它们的 `.env`。
- 同一业务中的请求模型、持久化、命令、投影和工具绑定分别放在职责清楚的模块。确实存在多个职责时才拆分，不按固定行数机械切片。
- React 19.3.1 与 TypeScript 7 前端按组件、状态服务和功能域组织，Vite 8 负责构建。网络流、会话恢复和持久草稿归状态服务，组件通过 `useSyncExternalStore` 订阅稳定快照；通过类型和公开方法传递依赖，避免循环导入。
- 保持公共包入口稳定。跨模块调用通过命名与类型体现合同，不增加无意义的转发层或通用 `utils` 大仓库。

具体路径见[模块地图](../guide/development.md)。

## 事实与副作用

工具参数、用户文本、图片和菜谱内容属于数据，不能改变权限。所有写入在服务端检查引用、阶段、版本和取消状态。

区分读取、展示、修改和等待。GET 不补写个人摄入，展示清单不确认备菜，倒数结束不完成步骤。业务操作提交后再发布结果，后续记录同步失败不能伪报已保存的真实动作未发生。

用 `revision` 校验并发，用 `action_id` 或业务标识处理重复。冲突保留草稿并要求复核，不悄悄覆盖。数据库事务内避免再开启同库独立写事务。

## 数据与错误

保留原文与来源，未知值使用 `null`，估算独立标识。食材身份、配方人数、制作量和个人摄入分别表达。

错误提供稳定 `code/message` 与适用的恢复信息，原始供应商异常和密钥不回传页面。输入错误、零结果、数据更新、版本冲突、取消和系统故障是不同结果。

同步只读后台操作取消后可能继续至超时，写入必须再次核对当前轮次；失败与取消不能写入半截成功历史。生产连接失败时明确说明，不以假回答替代。

## 验证与文档

重构优先运行现有行为回归，覆盖公开入口和边界；新增测试保护可能被拆分破坏的状态、事件和协议，不为每个转发函数建立镜像测试。

前后端共同变化时，运行 Python 测试、`npm --prefix apps/chefmate-playground/frontend test` 与 `npm --prefix apps/chefmate-playground/frontend run build`，并检查真实 HTTP、构建资源加载、浏览器控制台与桌面/窄屏/横屏。使用隔离会话数据库；数据库写测试使用随机 schema，模型验收明确标出真实调用。

前端源码和样式位于 `frontend/src/`。`main.tsx` 导入 [styles/index.css](../../apps/chefmate-playground/frontend/src/styles/index.css)，由 `foundation/controls/shell/chat/details.css` 分别管理颜色与字体角色、公共控件、页面框架、聊天及详情布局。设置、个人中心和厨房样式随功能域组织，并限定在各自根容器；使用共享的 `--color-*`、`--font-*`，避免跨页面覆盖同名控件。

共享 Select 与文本输入样式归 `components/ui/`；新表单复用既有控件，保持主题、键盘、焦点、禁用和错误提示一致。开发者目录与轨迹归 `components/developer/`，普通对话不显示诊断数据。长设置页索引、弹出菜单与专注动画需在浏览器核对实际滚动容器和命中位置，组件测试不能替代布局验收。

`frontend/public/` 只保存字体、品牌和第三方图标资源。生成的 `web/` 由 FastAPI 提供 SPA 页面和 `/static` 资源，不手工修改构建输出。直接使用 uv 启动前先运行 `npm ci` 和构建；`run.ps1` 自动按这个顺序执行。视觉验收同时检查浅色、深色、字体角色、估算开关、窄屏和横屏，以及实际加载的构建资源。

当前规范放在 `docs/design`，原理与案例放在 `docs/guide`，参数放在 `docs/reference`，计划和验收放在 `docs/engineering`。README 保持产品入口与运行路径，用链接承接详细合同，避免不断追加日期小节。

文档移动后运行 `scripts/check_docs.py`，发布包后检查公共导入与必要资源。

## 版本与发布

版本号只在用户明确要求时升级。日常更新保持当前版本，有用户可见变化时才在 [releases.json](../../apps/chefmate-playground/releases.json) 累计日志，同一版本可以有多条记录。用户要求发版时，再汇总更新说明，并保留原始提交来源及历史档案供追溯。确定升级版本后，同步修改 App 的 `pyproject.toml`、`uv.lock` 和前端 `package.json`、`package-lock.json` 中的项目版本。

每条更新记录都包含 `source: {branch, commit}`：`branch` 保存当时的 Git 分支名，`commit` 保存被记录的已存在代码快照的完整 SHA，界面展示短提交 ID。来源固定保存在记录中，不在读取时动态取 `HEAD`，也不要求填写承载日志记录的提交自身哈希。

用户要求把近期条目合并到新版本时，使用 `includes: [{branch,commit}, ...]` 保留被合并记录的来源；旧版本中移除这些重复条目，原始历史仍可在 Git 与工程档案追溯。只更新文档时保持当前版本，不给用户更新日志追加内部文档整理。

较大更新完成并检查通过后，自动创建范围明确的提交并推送，无需再次确认；保留无关的本地改动，不提交密钥、个人配置和运行数据。

面向用户的更新日志用直白的话说明新增了什么、哪里更好用、哪些问题修好了，优先写用户在界面和操作中能感受到的变化。后端重构、模块拆分与文档整理等工程细节放在工程记录，不写进用户更新日志。

工程记录保留改动范围、验证命令、结果及限制。提交与推送完成后核对远端分支，确认交付的是已验证的版本。
