# 账号、用户工作区与管理平台

ChefMate Next 使用账号密码注册和登录。新账号通过欢迎引导了解对话、厨房任务、个人菜谱和食光手记，设置称呼、烹饪经验、用餐人数、偏好和主题。欢迎配置未完成时，服务端拒绝业务接口；不是只依赖页面遮罩。

具体界面操作见[账号与管理员指南](../guide/accounts.md)。

## 身份和权限

密码使用随机盐 scrypt 哈希，会话使用高熵随机 Cookie，服务端只保存令牌哈希。Cookie 设置 HttpOnly、SameSite=strict，HTTPS 部署开启 Secure。账号名称归一化后唯一；登录、注册有服务端限流，错误消息不回显密码。修改密码、停用账号或改变角色会撤销旧会话。

管理员通过显式部署配置初始化。首个注册用户仍是普通用户；已有普通账号不能因重启被提升为管理员。数据库事务保护最后一个可用管理员。

| 能力 | 普通用户 | 获准开发者 | 管理员 |
| --- | --- | --- | --- |
| 自己的对话、菜谱、收藏、记忆、手记、外观 | 可读写 | 可读写 | 可读写自己的工作区 |
| 调试目录、自己的原始上下文、工具直调 | 拒绝 | 开启开发者模式后可用 | 可用 |
| 全局模型、密钥、组件、运行和上下文预算 | 拒绝 | 拒绝 | 管理平台维护 |
| 用户、金额额度、价格、用量统计、金额核对、数据归档重置 | 拒绝 | 拒绝 | 可管理 |

浏览器开关与 `X-ChefMate-Developer` 只表达用户意图，不能授予权限。每次请求从有效会话重新读取当前角色和权限。所有写请求核对 Origin 的协议与主机以及浏览器的跨站标记，部署地址受 Host 白名单约束。

## 存储与隔离

Docker 默认运行独立的应用 PostgreSQL 服务。身份、会话、额度和审计位于账号 schema；每个随机用户 ID 对应独立的业务 schema。每个工作区分别构造仓储、Agent、个人检索包装与工具绑定。客户端没有选择目标用户的参数；拿到其他用户的对话或图片 ID 仍只能查询自己的工作区。

公共 PostgreSQL 菜谱目录是默认独立的数据服务，与个人数据分开。首次空库启动自动校验并导入仓库自带的 358 道基础菜谱，已有库不会在重启时被覆盖。图片和设置仍使用应用持久卷。源码离线测试和旧数据迁移保留 SQLite 适配，Docker 部署不以 SQLite 保存个人业务数据。逻辑路径用于图片与设置定位，不代表业务数据存放在同名文件中。

浏览器身份变化后卸载工作区、清理内存与界面缓存；图片草稿按账号分区。退出不会删除已保存的服务端数据。管理员重置个人数据必须输入完整账号，先归档再建立新工作区，身份和用量账本不随之清空。

旧单用户 SQLite 不会自动归属于新注册账号。迁移前停止旧服务、保留完整备份，通过显式迁移工具导入隔离环境，再核对数量和实际内容。不会通过删除现有数据解决升级问题。

## 欢迎配置与长期记忆

厨房档案、手写偏好与助手总结分别保存。称呼作为独立身份上下文始终随请求发送，不写入聊天历史的用户文本；经验、人数、口味、手写偏好和总结受同一个开关控制，欢迎引导与个人偏好页同步。

个人偏好服务在同一个数据库事务中更新账号档案、记忆开关与偏好投影，并用包含账号档案及记忆版本的 CAS 防止覆盖。旧授权迁移采用保守交集，既有关闭设置不会自动变成允许；用户曾清空的投影也不会因升级或改称呼而恢复。新的“清空长期记忆”只清除助手总结。当前对话中的明确要求优先于历史偏好。

## 额度、用量与价格

用户额度只按人民币金额管理，Token 用于统计。资金分为永久基础、永久充值与限时会员，依次优先使用较早到期的会员、基础、充值；每份会员同时受周与 5 小时窗口限制。可用余额为各会员两个窗口剩余值的较小值之和，加永久余额，再扣除对应来源的预留与消耗。基础不限额的旧账号保留该属性。金额以整数微元保存。

会员从授予时生效，窗口从首次实际使用起算，5 小时窗口截断到所在周与会员到期点。不可变窗口与按模型轮次划分的分摊记录共同保存首次归属；跨界结算、未知用量修正、进程恢复和人工核对不会把旧窗口费用或退款转到新窗口。充值与会员授予使用管理员提供的幂等请求 ID，重试不会重复发放。旧金额上限和历史用量迁入基础来源，不重发 ¥5，也不抹除已用金额。

管理平台可控制开放注册和新用户默认金额。初始默认 ¥5，可用 `CHEFMATE_NEW_USER_COST_LIMIT_MICROS=5000000` 改变首次初始化值；政策持久化后以后台为准，只作用于后续注册用户。旧 Token 字段只作为兼容数据保留，不参与任何准入。旧版只有 Token 上限的账号一次性改为站点金额默认，原本零额度仍为零，已有明确金额额度及明确不限额配置保留；这是额度模式迁移，不是 Token 与金额的任意换算。

开始一轮时在事务中预留金额；进入每次模型请求之前按输入字节、图片保守值、输出限制、重试次数和当时单价计算预留，防止并发越过金额余额。初始计价为未确认，有限金额用户不能调用模型；管理员显式确认输入、缓存输入和输出单价后才放行。允许明确确认全零单价用于免费模型，此时后续调用金额为零。

调用完成按模型报告和价格快照结算，取消、错误和中断同样记录。唯一轮次 ID 保证重放不重复扣减，删除聊天不删除用量。未报告完整 usage 的部分保持未知，其保守预留单列为暂估金额占用；不能把缺失用量伪装成实测零成本。

管理员可在用户用量明细中按供应商记录核对一轮的最终总金额，填写必需的核对原因。核对单独追加，不改写原始 Token、单价、金额和未知用量标记；最新核对金额替代该轮原金额与暂估金额参与余额计算，Token 仍保持原始报告。运行中或仍有预留的轮次不可核对，版本检查防止两个管理员覆盖彼此；完整核对历史与操作审计保留。

每次模型返回完整实测用量后，下一轮会释放已证明未使用的预留，避免多轮工具调用一直累加粗估上界。SDK 提供确切重试次数时据此保留之前重试的未知用量；没有次数元数据且启用了自动重试时，保留配置上界作为估算。默认自动重试为 0。已报告的部分输入、输出或调用不会因其他调用缺失数据而丢失，也不会跨调用拼凑出一个虚假的完整总量。

模型连接保存在账号库的私有配置中，每个连接包含提供商、协议、端点、模型、专用密钥与人民币单价，当前只激活一个。密钥不回显；更换提供商或端点来源需要新密钥或明确清除。连接编辑、启用和删除使用版本检查，执行中拒绝替换运行配置。测试备用模型使用该模型保存的单价与原生工具小请求，记录结果是否因后续编辑而过时。

每轮保留准入时的模型与价格快照，之后调价不改历史金额。仅支持 CNY。这里提供站内额度与可追溯计价，不包含真实支付、自动充值或供应商发票自动对账；图片、推理、封装和供应商 Token 算法差异仍需结合提供方账单核查。

## 运维边界

当前部署采用单个 App 进程：运行中的 Agent 和取消事件仍由该进程持有。PostgreSQL 解决数据持久化和事务，不代表已经支持任意横向扩容；多实例还需要分布式任务与请求幂等协调。

`/healthz` 检查服务与必需的应用数据库，应用数据库断开时返回 503，恢复后可继续使用已有有效会话。登录页面和静态资源仍可打开；工作区存储错误返回不含连接凭据的提示。`/api/status` 在登录后显示模型、公共菜谱库与金额计价就绪状态。模型连接测试与真实对话是不同验收范围。部署、备份与恢复命令见[部署指南](../guide/deployment.md)，本轮实测见工程验收记录。
