# ChefMate 本地测试工作台

一个本地厨房工作台，连接真实菜谱检索、标准 LangChain Agent 和独立厨房任务服务。前端使用原生 HTML/CSS/JavaScript；FastAPI 负责应用配置、HTTP、SSE 与会话保存。

## 个性化厨房（2026-10-21）

- **食光手记**：首页突出今日热量、蛋白质、脂肪、碳水和每日趋势。拍照或文字记餐先生成草稿，聊天里直接展示食物、份量和营养；可以继续说“米饭减半”“确认保存”“看看最近一周营养”，或使用组件按钮。用户明确确认后才计入摄入，估算和未知值分别保留。做饭记录另存整餐制作量、尝试菜谱与做菜感受，不当作一个人的摄入；删除聊天不删除这些记录。
- **菜谱中心**：搜索和分页浏览原有菜谱、收藏喜欢的菜；上传截图或粘贴文字后由真实模型生成待核对草稿。桌面右侧核对、窄屏整页展开，内部按标签切换，保存后可用于选菜、备菜与烹饪。个人菜谱标记 `origin=user`，可移入回收站并恢复；通过助手删除时，必须先回答真实确认问题。
- **长期记忆**：设置里编辑个人口味与忌口；助手维护单独的简短总结。当前请求优先，用户记忆优先于助手总结；相关历史通过有界检索按需读取。关闭记忆开关或对应组件后停用读取与维护。
- **共享餐单**：`diners` 是整餐人数，默认 `portion_mode=shared`；单菜的 `target_servings` 是配方等效份量。五人四菜默认每盘2.5配方份，可按实际食量改动，源配方人数未知时保留原量及提示。
- **烹饪同屏**：做菜、提问、回复和输入框融合在同一屏；全部菜的步骤确认后，点击“完成本次菜肴”先保存，再自动续聊。顶部“继续做菜”可随时找回已保存的任务。
- **计时与主题**：浏览器页面打开时到期播放提醒音，可在设置里关闭或试听。计时保留服务端截止时间，刷新后恢复后台计时会话；浏览器需要一次点击或键盘交互解锁声音。主题支持浅色、深色和跟随系统，偏好保存在当前浏览器。

个人菜谱、收藏、饮食记录和长期记忆均保存在 `.runtime/sessions.db` 的独立表，不混入只读的 PostgreSQL 基础菜谱库。自定义菜谱复用 `chefmate-recipe-processing` 的菜谱契约验证与确定性营养计算；原文未给时间、人数和克重时保留未知，不直接让模型生成营养数字。

**系统组件**通过统一注册表绑定指南、提示词入口、工具、交互界面、依赖和工厂。六个内置组件为选菜与餐单、备菜与准备、烹饪引导、个人菜谱、长期记忆、饮食记录；关闭组件同时撤去模型可见工具与执行权限。共用阶段工具按目标阶段检查组件，已有记录保留。未来运动与体重等能力可以独立新增组件，复用个人饮食数据和同一测试边界。

设置按偏好、智能体、高级设置和关于整理，Token用量页提供一年、7天、30天、全部记录、每日热力图及模型分布。用量来自供应商报告，输入与输出均完整时可精确相加得到总量；未报告字段和不完整覆盖明确保留。删除对话保留独立用量账本。开发者模式左侧栏显示当前请求的系统、对话、工具调用、工具定义、界面、记忆和指南占用比例与粗略Token估算；右侧请求轨迹可选择实际请求并查看内容和供应商用量。普通模式隐藏这些观测入口。顶部“详情”可展开右栏，聊天和中心详情均支持拖宽并保存。

设置、菜谱中心和食光手记共用填充式原生控件、下划线标签和稳定的操作区；正文、指标和列表平铺呈现。详情保留列表位置，页签切换保留同一份输入；所有离开入口保护未保存修改，保存期间锁定字段。键盘可操作数字步进、开关和页签，手机详情约束焦点并支持 Escape 返回。

## 启动

在仓库根目录运行：

```powershell
uv sync --project apps/chefmate-playground --extra dev --python data_cleaning/.venv/Scripts/python.exe
uv run --project apps/chefmate-playground chefmate-playground
```

访问 <http://127.0.0.1:18765>。也可以执行本目录的 `run.ps1`，或用 `--port 端口号` 换端口。服务只监听本机地址。

本次开发已准备应用自己的 `.env`，复用了现有模型和测试数据库配置。该文件被 Git 忽略。其他环境从 `.env.example` 创建自己的 `.env`：

- `CHEFMATE_DATABASE_URL`：已有 PostgreSQL 数据库连接。
- `CHEFMATE_DATABASE_SCHEMA`：已有菜谱 schema，默认 `chefmate`。
- `CHEFMATE_USDA_DATABASE`：可选本地 USDA 库，相对路径以应用目录为基准。
- `OPENAI_API_KEY`、`OPENAI_MODEL`、`OPENAI_BASE_URL`：模型配置。
- `CHEFMATE_AGENT_TIMEOUT`、`CHEFMATE_AGENT_MAX_ROUNDS`、`CHEFMATE_AGENT_MAX_TOOL_CALLS`：单轮执行预算。
- `CHEFMATE_AGENT_MODEL_TIMEOUT`、`CHEFMATE_AGENT_MODEL_RETRIES`：单次模型请求超时与 SDK 重试次数；默认 120 秒、0 次，整轮预算默认 300 秒，失败由用户明确重试。
- `CHEFMATE_AGENT_STREAM_TOOL_CALLS`：模板默认 `false`，只有验证过所配置服务的标准流式工具协议后才打开。本机配置已启用：修正嵌套 schema 后，真实候选结果下的续轮请求已返回标准流式工具调用。
- `CHEFMATE_ENABLED_COMPONENTS`：逗号分隔的应用系统组件ID，默认 `meal-planning,pantry-preparation,cooking-guide,recipe-authoring,personal-memory,food-journal`。只允许注册表已声明的组件。早期开发已统一新配置格式，旧 `enabled_skills` 设置会明确拒绝。

应用读取自己的 `.env`，以及通过设置页保存的本地覆盖配置。库包不会自动读取清洗端配置。启动不会下载 USDA、启动数据库、迁移菜谱表或重新导入数据。

## 使用

先说“给我一个食材、时间和人数的表单”，填写“虾、30分钟、2人”，再说“按刚填的找几个”。也可以直接说“我想吃虾”。模型调用展示工具打开表单、菜品选择和详情；用户确认后保存餐单，继续备菜和烹饪。用户已明确说明的条件与食材状态，也可由助手填写并展示结果供核对。

当前支持 8 类组件：偏好表单、菜品选择、菜谱详情、餐单与份量、备菜清单、烹饪步骤、计时器、任务进度，另有等待用户回答的选项/自填交互。模型主动展示的核心组件可在聊天内直接操作，补充内容采用工作区入口，当前工作区一次展示一种内容；候选和清单分页，详情按食材/做法/营养/说明切换，烹饪逐步浏览。没有卡片内的嵌套滚动条；极长内容仍可通过页面区域滚动读取。表单修改在下一条自然语言发送前自动保存；菜品选择需要点击确认。勾选、份量、步骤和计时操作直接保存，下一轮附带服务端核对过的短快照。

阶段是会话状态，展示在标题和会话侧栏中。告诉助手“接下来准备食材”“备好了，开始做吧”“做完了”，由模型调用阶段工具，业务服务仍检查准备和完成门槛；网页不能直接跳阶段。`change_stage` HTTP 动作被拒绝，用户对实际食材/步骤的确认保留。

独立设置页提供单行摘要、展开轨迹和隐藏三种显示，偏好在当前浏览器保存。内容来自公开过程文本与实际工具调用，显示使用中、成功、拒绝/失败和中断；不提取模型隐藏推理字段。展开轨迹可继续展开公开说明或技术工具记录，最终回答独立显示。

时间和配方来自原始菜谱。可换算的用量按可靠份数依据缩放；原份数未知时保留原量并显示提示。备菜按具体菜品保留食材与状态。计时器保存 UTC 截止时间和暂停剩余量，刷新可恢复；全部备料经用户确认才能开始烹饪，全部步骤完成才能结束。

模型使用标准 `langchain.agents.create_agent` 和 middleware 执行模型/工具循环，按最新阶段筛选业务工具。组件指南先只提供简介，通用加载器 `load_skill` 按需读取正文；产品以系统组件统一配置和权限。具体职责和状态协议见[架构说明](../../docs/agent-ui-architecture.md)。

页面提供会话切换、停止、重试、真实菜谱卡片、详情和折叠的工具输入输出。未配置模型时显示明确状态，不使用假回答替代。停止本轮不会写入半截工具历史。切换对话或浏览器断开只分离实时视图，后台本轮继续运行；重新打开可恢复状态。停止按钮会取消模型调用。

本机当前使用经验证的原生流式工具传输，状态、工具事件和回答通过 SSE 更新。模板保守地关闭流式；其他模型服务需要单独验证协议能力。当前服务首个片段可能等待较久，因此模型请求与整轮预算分别配置，停止按钮可随时取消。

对话保存在 `.runtime/sessions.db`，与 PostgreSQL 菜谱库独立，不提交 Git。成功模型历史、真实工具结果和页面消息分别保存。失败或取消后可重试末条消息，不重复追加。服务重启会把未完成的本轮标为中断。

失败、停止或重启中断后的用户文字仍保留为下一轮的上下文。例如“想吃虾”失败后再补“半小时以内”，智能体仍知道要查虾；失败的工具结果和半截回答不会当作已完成证据。

## HTTP 接口

| 接口 | 用途 |
|---|---|
| `GET /api/status` | 模型配置、数据库状态和菜谱数量 |
| `GET/POST /api/sessions` | 会话列表 / 创建 |
| `GET/DELETE /api/sessions/{id}` | 恢复 / 删除未运行的会话 |
| `GET /api/sessions/{id}/workspace` | 当前完整组件与模型短快照 |
| `POST /api/sessions/{id}/actions` | 受控动作：`{action_id,base_revision,view_id?,type,payload}` |
| `POST /api/sessions/{id}/turn` | `{message, request_id?, retry?, ui_snapshot?}`；返回 SSE |
| `POST /api/sessions/{id}/cancel` | 停止当前轮 |
| `GET /api/components` | 系统组件及指南、工具、界面和依赖清单 |
| `GET /api/journal` | 个人营养、饮食草稿、已确认饮食与独立做饭记录 |
| `GET/PUT/DELETE /api/food-logs/{id}` | 读取、核对修改草稿、移入回收站；修改使用revision校验 |
| `POST /api/food-logs/{id}/publish`、`restore` | 用户确认记录、恢复记录 |
| `GET /api/usage?days=7\|30\|all` | 实际用量、覆盖率、每日和模型统计 |
| `GET /api/about` | 版本、菜谱数量及组件数量 |
| `GET/PATCH /api/settings` | 脱敏设置读取与版本校验保存 |
| `POST /api/settings/test-model` | 检查所选协议的原生工具调用与结果回传 |
| `GET /api/recipes/{recipe_id}` | 当前真实菜谱详情 |
| `POST /api/tools/{name}` | 直接测试四个只读查询工具 |

SSE 的 `data` 是 JSON，事件 `type` 为 `status`、`tool_start`、`tool_end`、`assistant_delta`、`ui_action`、`model_usage`、`context_usage`、`result`、`error`、`done`，并携带会话、本轮和递增序号。最终结果包含文字、菜谱列表、选定详情、工具调用、界面动作、快照、实际用量和 `suggested_replies: [{title,text}]`。推荐只随成功完成的回答返回；失败和取消不生成。密码、API Key 与原始供应商异常不会返回页面。

工作区以 `revision` 校验动作，`action_id` 防止重复提交。发生冲突会要求复核并保留草稿。后端重新构造模型上下文，客户端伪造的菜谱、勾选和条件不能作为业务事实；模型执行期间发生的用户修改不会被旧结果覆盖。

工具参数见[检索包](../../packages/chefmate-retrieval/README.md)、[工作流包](../../packages/chefmate-workflow/README.md)，执行约束见[智能体核心](../../packages/chefmate-agent/README.md)。

## 设置与聊天内交互（2026-10-14）

打开 `/settings`，偏好下有外观与对话、烹饪与计时、长期记忆；智能体下有模型连接、系统组件和Token用量；上下文预算、执行设置和开发者归入高级设置，另有关于页。模型设置支持 OpenAI Chat Completions 和 Responses；连接测试验证原生工具调用、工具结果回传与最终回答，不能把 HTTP 200 或文本工具标记当作成功。

模型、组件和预算的设置保存在被 Git 忽略的 `.runtime/settings.json`，覆盖应用 `.env` 默认值；数据库连接仍由 `.env` 管理。设置查询不返回密钥，空密钥仅在同一端点沿用，换供应商必须提供专用密钥。保存采用版本校验和原子文件替换；有对话执行时拒绝应用，等待结束后再保存。界面显示偏好保存在当前浏览器。

工作流工具新增 `display=inline|workspace|none`：模型主动选择本轮内容和展示位置；通常只展示一个核心组件。聊天默认最多展开两项，可在设置改成一项。读取工作区不会展示所有已有视图。聊天内组件使用服务端当前版本，与工作区共用草稿、动作标识和版本检查；旧组件替换后仅保留入口。详情在原位切换，返回时保留选择与分页。

执行时默认显示一行当前公开操作，完成后隐藏过程记录。设置页「开发者」可开启已完成记录、工具参数和真实 token/缓存统计；普通界面不展示数据/组件调试页签。记录采用平铺文字，不提取模型内部推理。仅左下角保留设置入口；窗口高度固定，长对话使用可见的细滚动条，列表仍分页。

备菜清单支持整餐或按 `recipe_ids` 展示单菜，可直接在聊天内切换。独立采购阶段与工具已移除，旧工作区读取为 schema 2 的备菜状态；明确勾选且来源可追溯的旧食材迁为已备，未知来源保持待确认。读取只做投影，下一次正常修改才原子保存新格式。

模型请求保留稳定系统提示和工具定义，动态状态放在对应用户轮次；相同快照仅发送变化，重复的成功只读查询在单轮内拦截，失败查询可重试。菜谱查询默认8条，更多结果支持分页。`usage` 记录模型服务实际报告的输入、输出、缓存读取与推理 token 数；缺失值为null，不能据此推断供应商支持缓存。前缀稳定有助于命中缓存，但不保证网关路由或缓存策略。

模型连接页只显示实际配置项，不内置供应商测试预设。2026-10-14 使用专用密钥验证 `https://apiclaude.cc/v1` 的 `gpt-5.6-terra`：Responses 协议与流式原生工具调用、结果回传通过。密钥只留在本地配置中。


上下文按消息JSON的字符数计量，默认总历史/当前轮工具预算400,000字符，单次工具结果60,000字符。此前分别为90,000和28,000。设置页「上下文预算」独立配置这两项，保存后应用到后续轮次并持久化；它们不是供应商模型的token窗口声明。已有完整旧轮次仍按边界清理，单轮超出配置仍明确拒绝。

设置与聊天共用主题和 ChefMate 图标，设置「界面显示」提供四个 SVG 候选。每次回复展开几项内容仅限制交互组件数量；内容间距只影响留白，两者都有具体示例。

「模型连接」可显式开启支持图片输入，不根据模型名字猜能力。聊天可选取或粘贴 JPG、PNG、WebP，模型连接页可设每次最多 1–12 张（默认 3 张）；浏览器先缩至最长边1600像素、JPEG约1.5MB以内，服务器重新解码、验证并去掉EXIF后保存。图片归当前会话所有，聊天和模型历史只持久化元数据，真正调用模型时才装载成 LangChain 原生图片块。每次模型请求的总图片数（含历史）遵守同一个上限，超出时按完整旧轮次清理，页面历史记录仍保留。未启用图片的模型拒绝新图片；切换为纯文本模型后不声称看到了旧照片。

会话标签由任务状态生成：闲聊 → 正在选菜 → 已选菜/备菜/烹饪 - 菜名。表单、选菜、份量和新增计时器的提交/放弃操作集中在输入框上方，草稿保留来源会话和版本，确认后再进入下一条消息的快照。

备菜、烹饪和菜谱步骤可全屏查看，长内容按可用高度分页，提供上一页、下一页和手势切换。交流共用同一个聊天输入框，退出后恢复到主聊天。模型可用 update_cooking_guidance 按用户补充的条件更新当前任务指导，保留原菜谱步骤、用量与真实勾选/完成进度；不会写回菜谱数据库。图片能力依赖所配置的外部多模态模型，不是自训练视觉识别。


## 工作台交互与视觉

图片以正方形缩略图显示在消息文字上方，点击在当前页面预览，支持方向键切换和 Esc 关闭。左侧会话栏可折叠，并可拖动右边界或聚焦边界后用方向键调整宽度；桌面宽度与折叠偏好保存在当前浏览器，手机使用抽屉式导航。

设置在主工作区中打开，对话、未发送文字和图片草稿保留。模型本轮完整输出结束后才展示新增交互组件；确认条件或菜品后先保存，再自动发送一条说明并继续模型处理。保存失败或版本冲突不会自动继续。

全站使用本地 Lucide SVG，配色由 `static/colors.css` 的语义变量集中管理，布局与响应式规范见 [视觉规范](../../docs/ui-design-system.md)。

新会话在首次发送前只存在于浏览器草稿，选图片也只生成本地压缩预览；发送时才创建会话、上传图片。空会话不出现在列表。开场随机抽取三张能力模板，填空和使用模板都只是编辑输入框，不会发送。

设置「对话建议」控制 `interaction.reply_suggestions`（默认开启，严格布尔值）。模型在正常轮次中通过 `suggest_replies` 提供三个不同方向的短标题和用户口吻草稿；缺少有效建议时按真实任务阶段给出保守默认，不再请求模型。点击推荐只替换输入文字，确认菜品等已有操作仍保存后自动续轮。建议完成后才出现，关闭设置会隐藏历史建议；服务器保留原记录。

全屏工作区与主聊天以水平滑动切换，保留页面底色。内容和长回复都按屏幕高度切成可翻阅卡片；输入框常驻底部，可以自然切换到助手交流。复用文字、图片草稿、实际等待/工具状态、停止与重试，退出全屏不会停止本轮回复。公开活动使用旋转图标和逐字提示，并尊重减少动态效果偏好。

## 用户回答与开发者上下文

`update_preferences`、`select_recipes`、`update_prep_items` 接受真实字段/项目ID和唯一的必填 `expected_revision`。偏好修改另需 `changed_fields` 显式列出修改字段，`values` 中未列字段即使被严格格式补齐也不会保存；非法null返回字段级错误。原子保存后已自动展示实际结果，不必重复show。助手根据用户明确意图操作；“小料”由模型结合真实清单判断，不维护猜测性的食材分类规则。版本冲突或其中一个项目无效时整批不写，先读取最新状态再处理。

`ask_user` 必须单独调用，提供问题、至多六个选项及可选自由填写。成功后通过标准直接返回工具结束当前执行，保持工具调用/回调闭合，不为等待继续请求模型。待回答问题持久化在工作区；输入区切为问答，会话显示小红点和“等你回答”。提交 `answer_question` 保存答案，随后用稳定 `answer:<question_id>` 自动续轮。动作和消息各自幂等；断线、刷新或切换会话仍可恢复。未回答时服务端拒绝新普通轮次。

开发者模式下，右侧「调试」提供工具目录、调用、组件、上下文四个视图。工具目录来自当前实际注册 schema，并标记阶段限制；日志展示输入和返回字段。每轮真正调用模型前记录语义请求，工具与模型用量更新可实时读取。普通会话/SSE只附不含正文的分类计量，不携带原始请求调试记录；独立调试表压缩保存最近20轮，删除会话同时清理。读取调试 API 要求显式 `X-ChefMate-Developer: 1`，这是本机显示开关，不是身份认证机制。

每次模型调用的上下文按以下顺序组织：

| 部分 | 实际内容 |
| --- | --- |
| 系统提示 | 固定 ChefMate 执行规则；开启时附加推荐回复规则；显式启用的组件指南名称与简介 |
| 历史消息 | 保留用户、助手原生工具调用、对应 `tool_call_id` 的结构化回调及最终回答；按完整轮次控制预算 |
| 当前用户消息 | 原始文字，随后追加服务器验证的任务状态；首次为完整快照，后续只发送变化 |
| 本轮工具循环 | 助手请求工具 → JSON结果/状态差异 → 下一次模型调用；组件指南经 `load_skill` 回调按需进入 |
| 图片 | 仅在启用图片能力时构成原生图片块；调试与普通历史只保留元数据 |

状态不会假扮用户指令，也不会单独重写成系统消息。工具定义作为调用接口绑定在请求上；组件指南正文不授予权限。开发者可展开实际系统提示、用户自然文字、附带状态、助手工具请求和工具回调；旧轮次没有捕获记录时明确显示缺失，不用当前配置重建并冒充。凭据、图片字节和供应商隐藏推理不进入调试记录。


## 工具错误恢复与阶段契约（2026-10-21）

任务revision只在真实业务状态变化时递增，纯展示仅递增presentation_revision。前端按两个版本识别较新展示，同业务版本的展示替换保留草稿，真实用户修改仍使旧写入冲突。选菜统一用select_recipes，可直接引用真实检索结果，自动进入planning；旧set_meal_plan仅保留历史/宿主兼容，不提供给新模型请求。

任务快照包含current_actions、allowed_transitions和具体blockers，模型每次只绑定当前可执行工具，后端使用同源规则再次校验。没有餐单不能凭阶段枚举进入planning；先按用户授权建立餐单。修改/展示操作不与其他工具同批，必须等实际结果；只读查询允许并行。

相同工具参数连续失败三次后进入无工具的收尾请求，保留已查到的真实结果并说明未成功操作；推荐回复只尝试一次，失败回落默认草稿。生产请求与连接测试均校验原始工具参数完整性，开发者上下文可展开参数完整性摘要，不记录参数片段或凭据。
